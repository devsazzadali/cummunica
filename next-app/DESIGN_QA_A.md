6. **F6 — Dead fake-call component remains in source.** `src/components/interactive.tsx` `CallShell` still renders a simulated timer ("00:00 · Simulated timer") and "Call quality: Good (placeholder — real quality from Step 4 WebRTC stats)" with a demo video placeholder. Grep confirms NO page imports it (the real `/call` page uses `CallScreen`), so it is not user-facing today — but dead fake-call code in the shipped source is a FAIL under "no fake data pretending to be real" hygiene and must be deleted (likewise the unused `DemoButton`/`DemoFormNote` and the unused `demo-data.ts` CHATS/MESSAGES/STATUSES/CALLS/COMMUNITIES exports; only `initials()` and the SAZMU presets are actually imported).
7. **F7 — Group creation bypasses the block check (security FAIL, inconsistency).** `POST /api/chats` GROUP adds `memberIdentifiers` with NO `isBlockedEitherDirection` check, while `POST /api/chats/members` (admin add) DOES refuse blocked users (`"cannot add a blocked user"`) and DIRECT chat creation DOES refuse them. Fix: apply the same blocked check in GROUP creation (and decide/document the group-message rule — see next point).
8. **F8 — Block does not cover group messages or contact requests (security gap).** `POST /api/messages` refuses blocked users only for `DIRECT` chats, so a blocked user who is already in a shared group can still message the blocker there; `POST /api/contacts` has no blocked check, so a blocked user can still create a contact-request row (chat creation and calls still refuse them, so this is a request-creation leak, not a message/call bypass). Fix: either refuse contact creation when blocked either way, or document explicitly that block is 1:1-only and group membership is a separate admin decision.
9. **F9 — Partial-ID search is not absolutely rejected server-side (spec FAIL, edge case).** `searchUsers` sends any digit-only non-8-digit query to the username prefix search. Usernames may be digit-leading (`^[a-z0-9_]+$` allows `12345`), so a partial ID that is also a username prefix can return a user. The client warns, but the server does not reject digit-only queries outright. Fix: in `searchUsers`, return `[]` (or 400) for digit-only queries that are not exactly 8 digits, before the username search.
10. **F10 — Message media URLs are unrestricted (validation FAIL).** `POST /api/messages` accepts any non-empty `mediaUrl` for PHOTO/VOICE/VIDEO/FILE and renders it as `<img>`/`<video>`/`<audio>` src, while status media and profile avatars correctly require `/uploads/`. An attacker can inject arbitrary external URLs (tracking, phishing imagery, MIME mismatch — `mediaMime` is also unchecked). Fix: require `mediaUrl` to start with `/uploads/` for media messages, exactly as status/profile already do.
11. **F11 — Upload MIME is client-supplied only (validation gap).** `/api/media` trusts `file.type` from the multipart upload; there is no magic-byte/content sniffing, so a renamed non-image file with an `image/jpeg` type is stored (under a forced `.jpg` extension) and served from `public/uploads/`. Fix: sniff content bytes server-side and reject MIME/extension mismatches (and consider a content-type header policy for served uploads).
12. **F12 — Login rate-limit/lockout can be diluted via `x-forwarded-for` (security gap).** `clientIp()` trusts the first `x-forwarded-for` value with no trusted-proxy configuration, so a caller who sets that header can rotate apparent IPs and dilute both the 20/10-min per-IP limit and the per-(IP + identifier) lockout. Fix: only trust `x-forwarded-for` behind a configured trusted proxy, or key the lockout to the identifier as well as the IP.
13. **F13 — No Content-Security-Policy header (defence-in-depth FAIL).** `next.config.mjs` sets nosniff/DENY/Referrer/Permissions-Policy (verified live) but no CSP and no HSTS. With tokens in localStorage (F20 below), a CSP is the main second layer against script injection. Fix: add a restrictive CSP (and HSTS at the host) — camera/mic must remain allowed for WebRTC.
14. **F14 — Bengali font is named, not loaded (design FAIL).** No `@font-face` / `next/font` / webfont import for Noto Sans Bengali or Hind Siliguri exists; rendering falls back to whatever the device has. Fix: bundle or load the Bengali font properly, then re-verify visually.
15. **F15 — Muted-text contrast fails on chat/screen backgrounds (design FAIL).** `#667781` on `#ECE5DD` is 3.72:1 and on `#F0F2F5` is 4.14:1 — below AA for 12px metadata text (bubble timestamps, previews on those backgrounds). It passes on white (4.65:1). Fix: darken muted text used on `#ECE5DD`/`#F0F2F5`, or restrict muted small text to white surfaces.
16. **F16 — SAZMU composer attach/photo/voice buttons are demo-only on a live page (fake-affordance FAIL).** On `/sazmu`, `Composer`'s Paperclip/Photo/Mic buttons only set a demo note ("Demo only — your message was added on this screen only. It was not sent to a server (Step 3 wiring)") — stale Step-3 wording on a live page, while text sending is real. Fix: either wire SAZMU attachments/voice for real or remove those buttons from the SAZMU composer.
17. **F17 — Last-admin protection bypass via chats PATCH leave (security inconsistency).** `PATCH /api/chats {action:"leave"}` deletes the caller's membership with no admin check, while `DELETE /api/chats/members` correctly blocks the last admin leaving while others remain. A last admin can therefore orphan a group via the chats route. Fix: apply the same last-admin check in chats PATCH leave.
18. **F18 — Call-outcome leak to non-parties (information-disclosure FAIL, low exploitability).** `GET /api/calls?callId=` checks party membership when the call is still active, but the `callOutcomes` branch returns the outcome (MISSED/DECLINED/CANCELLED/ENDED) to ANY authenticated caller without a party check. Call IDs are random UUIDs (so guessing is impractical), but the check is still missing. Fix: record the parties with the outcome and enforce the party check on that branch too.
19. **F19 — Delete-for-all does not redact server-side (privacy FAIL).** `DELETE /api/messages` sets `deletedForAll=true` but keeps `text`/`mediaUrl` in the row, and `GET /api/messages` returns them unchanged — clients render a placeholder, but any member can still read the "deleted" content via the API. Fix: strip `text`/`mediaUrl`/`mediaMime` for `deletedForAll` messages in GET responses (or null them on delete).
20. **F20 — Token storage + single-process state remain production limitations (standing, not new).** JWTs live in `localStorage` (not httpOnly cookies — a token copied before logout stays usable until expiry or logout, and XSS impact is higher); revocation blocklist, rate-limit buckets, login locks, and the active-call map are all in-memory/single-process, so a multi-instance deploy can serve a revoked/locked-out token on another instance. Both are documented in SECURITY.md and still open; they do not block the unit/code gates above, but they block a production PASS.
21. **F21 — Settings/profile avatar has no UI (functional partial).** `PATCH /api/profile` supports `avatarUrl` (restricted to `/uploads/`), but `/settings` exposes no avatar upload/change control. Fix: add avatar upload to Settings or document it as pending.
